User manual

sqlcli, a terminal SQL client for Oracle

A split-screen client with connections, a SQL editor with JOE keybindings and a results grid. Settings live in a TOML file, and every statement you run is saved to a searchable SQLite history.

Startsqlcli -c ora
Run statementF5  whole buffer F7
Quit^K X

02Building

cd sqlcli
make build          # same as: go build -o sqlcli ./cmd/sqlcli

The result is a single binary, ./sqlcli. Copy it anywhere on your PATH.

03Starting sqlcli

sqlcli                      # choose a connection in the left pane
sqlcli -c ora               # connect to the saved connection "ora" at start
sqlcli -config ./my.toml    # use a different configuration file
sqlcli -l                   # list the saved sessions and exit
sqlcli -s "daily reports"   # start with a saved session (all its SQL tabs)
OptionMeaning
-c NAMEConnect to the saved connection NAME (case-insensitive) on startup. sqlcli exits with an error if no such connection exists.
-config PATHConfiguration file to use. Default: ~/.config/sqlcli/config.toml.
-lList the saved sessions (name, time saved, number of tabs, connections) and exit.
-s NAMEStart with the saved session NAME: its tabs, their SQL and connections (see Sessions). The connections panel and object tree are shown as usual (ui.show_connections). sqlcli exits with an error if no such session exists. Can't be combined with -c.
-versionPrint the version (sqlcli 0.1) and exit.

On first start, if the configuration file doesn't exist, sqlcli creates it with default settings and an example connection.

To quit, press ^K X, or Ctrl-C when no query is running. If a transaction is open, sqlcli asks for confirmation and rolls it back.

04The screen

Copying with the mouse. Drag with the left button to select, and the selection is copied to the clipboard when you release the button (the status bar says what was copied):

  • SQL editor: the dragged text is marked as a block and copied. Like any block, F5 then runs just that selection. A plain click clears a selection made by dragging (a block marked with ^K B / ^K K stays until ^K A).
  • Results grid: the dragged rows are copied as tab-separated values, one row per line, NULL as empty, ready to paste into a spreadsheet.
  • DBMS_OUTPUT text: the dragged lines are copied.

sqlcli copies with the terminal's OSC 52 sequence, which most terminals and tmux support (also over SSH), and with the system clipboard through the github.com/atotto/clipboard library (on Linux it needs xclip, xsel or wl-copy installed; macOS and Windows work natively). Hold Shift while dragging for the terminal's own selection.

Adding a connection

Pressing a asks these questions on the bottom line:

  1. Connection name. Any label. You use it with -c.
  2. User. The database user.
  3. Connect string. One of:
    • a TNS alias from tnsnames.ora, e.g. ORCL.EXAMPLE
    • Easy Connect, e.g. dbhost:1521/ORCLPDB1
    • a full descriptor, e.g. (DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=dbhost)(PORT=1521))(CONNECT_DATA=(SERVICE_NAME=orcl)))
  4. Password. Shown as *. Leave it empty to read the password from an environment variable instead, then enter the variable name (default SQLCLI_PASSWORD).
  5. Read-only? yes refuses DML and DDL on this connection (read_only). Pre-filled with no.
  6. Connect as SYSDBA? yes connects with the SYSDBA role (sysdba). Pre-filled with no.

Added and deleted connections are saved to the configuration file straight away. Press Esc at any question to cancel. A name another connection already uses is refused.

Editing and viewing a connection

e edits the selected connection. sqlcli asks, on the bottom line, for:

  1. Connection name, user and connect string, each pre-filled with the current value; Enter keeps it.
  2. New password, hidden as you type. Leave it empty to keep the current password setting. A typed password is stored in the config file and replaces a password_env setting.
  3. Password env var (only when you left the password empty), pre-filled with the current variable; clear it for none.
  4. Read-only? and Connect as SYSDBA?: yes or no, pre-filled.

Nothing is saved until the last answer; Esc at any question cancels without changes. A name another connection already uses is refused. Connected tabs keep their old settings until you reconnect them (Enter).

v shows the selected connection's settings: name, user, connect string (and whether it's a TNS alias, Easy Connect string or descriptor), where the password comes from (never the password itself), read-only, SYSDBA, which tabs have it open, and the config file. Any key closes it.

Switching connections is refused while a transaction is open: roll back (F8) or commit (F9) first. Read-only connections (read_only = true in the config file) allow only SELECT, WITH, EXPLAIN and DESC.

Passwords

A password typed in the wizard is stored in plain text in the configuration file. sqlcli writes that file with mode 0600, so only you can read it. With password_env the password never touches the file.

Tabs: several SQL panels and connections

Each tab is a separate SQL panel with its own editor, results, status and its own Oracle session. Tabs can use the same connection or different ones, all at the same time.

  • Separate sessions mean separate transactions: a change made in tab 1 is invisible in tab 2 until you commit it, and F8 / F9 only affect the current tab.
  • A long statement in one tab doesn't block the others. Switch tabs and keep working; the result appears in its own tab when it finishes.
  • Ctrl-C cancels the statement in the current tab only.
  • Closing a tab with an open transaction asks first and rolls it back. Quitting lists every open transaction and running statement before it asks.

Object tree

The bottom of the connections panel shows the objects of the current tab's schema, grouped: Tables, Views, Materialized views, Packages, Procedures, Functions, Types, Sequences, Synonyms, Triggers and Indexes (with counts). Tables and views open to their columns with types (ID NUMBER(5) NOT NULL), packages to their functions and procedures. Invalid objects are marked ✗. The tree loads when a tab connects, follows the active tab's connection, and is loaded again after CREATE, DROP, ALTER or RENAME.

A click selects, a double-click opens, the mouse wheel scrolls.

Filter. / (or f) asks on the bottom line for a filter and the tree follows as you type: only objects whose name contains the text are shown (case-insensitive; * or % match any text, e.g. emp*hist), groups without matches are hidden, the others open and show matching/all counts, and the first match is selected. The filter is shown on the last line of the tree (/ emp 3 matches). Enter keeps it, Esc goes back to the previous filter, and an empty filter — or x in the tree — shows all objects again. Each connection's tree keeps its own filter, also when it is reloaded (r).

Ctrl-D opens a new SQL tab (with its own session on the same connection) holding the object's DDL from DBMS_METADATA.GET_DDL: for a package its specification and then its body, for a type its spec and body. Statements end with ; or /, so the tab can be run as it is (F7). The title shows DDL PACKAGE NAME, and ^K D offers name.sql as the file name. On a column or a package member, Ctrl-D uses its table or package. Reading the DDL doesn't open a transaction.

Search and replace. ^R asks for the text to find and its replacement; ^K F does the same when you answer the options question with r (add c to match case, or a to replace every match without asking). The search starts at the cursor, wraps at the end of the buffer and stops where it started. Each match is highlighted and the bottom line asks: y (or Space) replaces it, n skips it, a replaces it and all the rest, Esc stops. The status line says how many were replaced; one ^_ undoes the whole replace.

File names may start with ~/. Tab completes file names in these questions (and when saving, loading or exporting): a single match is completed fully (directories get a /, so the next Tab looks inside), several matches are completed as far as they agree and listed in the status line, and Tab again steps through them. Hidden files are offered when the name starts with ..

Saving the SQL panel (^K D) asks for the file name, offering the tab's last file (or query.sql the first time). Saving again to the same file doesn't ask; another existing file is replaced only after you confirm. The file name is then shown in the SQL panel's title (SQL · ora · report.sql). ^K D also works from the connections and results panes.

Loading a file (^K I) replaces the SQL panel's text with a text file, puts the cursor at the top-left corner, and makes it the tab's file: the title shows its name and ^K D saves back to it. ^_ (undo) brings back the previous text. Directories, binary files and files over 10 MB are refused. To insert a file at the cursor instead, use ^K R.

Code completion

With editor.completion = true (the default) the editor suggests what to type next.

 1 select e.sa 
 2    SALARY        column 
 3    SALES_REGION  column 
 4 from employees e
  • The list opens by itself once you've typed two letters of a word and something matches, and right after a . (e. for an alias). Ctrl-Space opens it at any time.
  • It offers the columns of the tables in the current statement first, then tables, views and synonyms of your schema, other objects (sequences, packages, procedures …), SQL keywords, functions, data types and public synonyms (DUAL, DBMS_OUTPUT …).
  • After alias. or table. it lists only that table's columns. Aliases come from the statement's FROM and JOIN clauses.
  • After package. it lists the package's functions and procedures (testpkg. → CALL1 function, CALL2 function), also for standard packages through their public synonyms (dbms_output. → PUT_LINE …) and with an owner (men.testpkg.). Overloaded subprograms are listed once.
  • Object names load in the background when a tab connects (once per connection). Columns load from the data dictionary the first time they're needed, following synonyms. After CREATE, DROP, ALTER or RENAME the names load again.
  • The inserted text follows how you type: emp gives employees, EMP gives EMPLOYEES. Names that need quotes get them.

07Running SQL

KeyRuns
F5The marked block, or else the one statement the cursor is in. Ctrl-Enter and Alt-Enter also work if your terminal sends them.
F7The whole buffer as a script
Ctrl-CCancels the running statement

Statements run one after another. If one fails, the rest are skipped. The results pane shows the last query result, or the messages of all statements.

How statements are separated

sqlcli follows SQL*Plus conventions:

  • A plain SQL statement ends with a ;, at a blank line, or at a line holding only /. The ; can be anywhere on a line, so one line can hold several statements. A ; inside a string ('a;b') or a comment doesn't end a statement.
  • A PL/SQL block ends only at a line holding only /, so it can contain blank lines and semicolons. PL/SQL blocks start with DECLARE, BEGIN, CREATE [OR REPLACE] PROCEDURE | FUNCTION | PACKAGE | TRIGGER | TYPE, or WITH FUNCTION / WITH PROCEDURE (a query with inline PL/SQL). sqlcli also follows the block structure (BEGIN … END, nested procedures and functions, CASE, END IF / END LOOP, a package's initialisation section), so a unit also ends at its last END …; without a /: a package spec, its body and a SELECT using it can follow each other directly. A line starting with CREATE, ALTER, DROP, GRANT or REVOKE always starts a new statement. Type specs, external (LANGUAGE JAVA / C) procedures and WITH FUNCTION queries still need the /.
  • Strings may use Oracle's q'[…]' quoting ([], (), {}, <> or any other delimiter); ;, ' and comment marks inside are just text.

Creating PL/SQL objects. After CREATE of a procedure, function, package, package body, trigger or type, sqlcli reports PACKAGE BODY X created., or, if Oracle found errors, … created with compilation errors. in red with the errors listed in the results pane, like SQL*Plus SHOW ERRORS. In 4/5 PLS-00201: …, 4/5 is the line and column inside the object. An F7 script continues after an object with errors and lists the errors of every statement.

Comments (-- … and /* … */) before and after a statement are skipped: they aren't sent to Oracle and aren't saved in the history. A part of the buffer that holds only comments isn't a statement at all, so commented-out SQL never runs and never breaks an F7 script. Comments inside a statement stay, including optimizer hints (/*+ … */).

With the cursor inside a comment, F5 runs nothing (the status bar says so): anywhere in a /* … */ block, or anywhere on a line that holds nothing but comments (also just after a closing */, or on the indentation before -- note). A -- comment at the end of a line with code is different: with the cursor in it, F5 ignores the comment and runs the statement before it (select * from emp; -- all rows). A marked block runs as usual, wherever the cursor is.

One statement per F5

F5 runs exactly one statement: the one the cursor is in. The position just after a statement's closing ; still counts as inside it. On a blank line, the statement above runs.

The trailing ; or / is removed before the statement goes to Oracle. PL/SQL blocks keep their final ;, which Oracle requires.

select * from netlist;
select * from nsm;
select 1 from dual; select 2 from dual;

update emp set sal = sal * 1.1
 where empno = 7369

begin
  dbms_stats.gather_table_stats(user, 'EMP');

  dbms_output.put_line('done');
end;
/
  • Cursor on line 1, F5: runs only select * from netlist.
  • Cursor on line 2, F5: runs only select * from nsm.
  • Line 3: where the cursor sits on the line decides which select runs.
  • Cursor on either line of the update, F5: runs the update. It has no ;; the blank line ends it.
  • Cursor anywhere in the PL/SQL block, including its blank line, F5: runs the block.
  • F7: runs all six statements in order.

To run several statements with one key, mark them as a block (^K B … ^K K) and press F5, or press F7 for the whole buffer.

SQL*Plus commands

sqlcli understands the SQL*Plus commands used most, typed in the SQL panel or in scripts. Each takes one line and is read as written, so quotes and ; in it are just text (a trailing ; is optional). Commands can be shortened as in SQL*Plus (DESC, SHO ERR, PRO, DEF, SPO, STA).

SET TRANSACTION, SET ROLE and SET CONSTRAINTS are SQL and go to Oracle. HOST isn't supported.

DESC shows, for a table, view or synonym, each column with NULL? and its type as SQL*Plus shows it (NUMBER(10,2), VARCHAR2(30 CHAR), NOT NULL); for a package every function and procedure with its arguments, types, IN/OUT, defaults and return type. owner.name works and synonyms are followed.

Substitution variables. &name and &&name are replaced by the value of a DEFINEd variable, also inside strings (where ename = '&who'); a . right after the name ends it (&tab._history). Comments are left alone. A variable without a value makes sqlcli ask for it before anything runs; &&name and ACCEPT keep the answer for later statements, &name uses it for this run only. Variables belong to the tab. Substitution is on at start (query.substitution = true); text like 'A&B' then asks for B, so use SET DEFINE OFF (or substitution = false) when your SQL contains &.

Scripts can call scripts (@@ relative to the caller), up to 20 deep; their statements run one after another like F7 and stop at the first error.

SPOOL writes each statement (as SQL> …), query results as a text table, messages, compilation errors and output to the file until SPOOL OFF (or until sqlcli ends). Only rows fetched when the query ran are written (query.max_rows).

08Transactions

By default (query.auto_commit = false) changes are not committed automatically.

  • INSERT, UPDATE, DELETE, MERGE, PL/SQL blocks and CALL start a transaction if none is open. The status bar shows TX.
  • F8 rolls back and F9 commits. You can also run COMMIT or ROLLBACK as statements.
  • Quitting with an open transaction asks for confirmation and rolls it back. Switching connections is refused until you commit or roll back.
DDL commits

DDL (CREATE, ALTER, DROP, TRUNCATE, GRANT and similar) makes Oracle commit the open transaction before it runs. sqlcli says so in the message and clears the TX marker.

With auto_commit = true, every statement is committed as soon as it succeeds, and TX never appears.

Editing cells

The grid has a cell cursor: ← / → move it between columns (the grid scrolls sideways to keep the column visible), ↑ / ↓ between rows. u edits the current cell: the bottom line asks for the new value, filled in with the current one; an empty value sets NULL (for text that's the same in Oracle). sqlcli then runs UPDATE table SET column = :value WHERE ROWID = :rowid with bind variables, in the tab's transaction like any DML: F9 commits, F8 rolls back, and after a rollback the edited cells show their old values again (with query.auto_commit = true each change is committed at once). Numbers may use . or ,; dates are typed as YYYY-MM-DD [HH:MI[:SS]].

CLOB columns (CLOB, NCLOB) open in a full-screen text editor panel instead of the one-line prompt, with the current value and the editor's JOE keys (blocks, ^Y, undo, paste). ^K X or Ctrl-S saves and runs the UPDATE; Esc cancels — with unsaved changes the first Esc warns and the second discards them. Saving an empty text sets NULL. The same panel asks for CLOB columns when inserting a row (i). Values are sent as LOBs, so they may be longer than 32 KB. Windows line ends (CR LF) are kept: the panel shows plain lines and saving puts the CR LF back; a value you didn't edit is saved exactly as it was. (Tabs are shown and saved as spaces once you edit the value.) The record view, too, shows CR LF and CR as line breaks.

In the text editor panel ^K D saves the text to a file and ^K I loads a file, replacing the text (^_ undoes); ^K R inserts a file at the cursor and ^K W writes the marked block to a file. The first name offered is table_column.txt (e.g. docs_doc.txt), then the last file used; Tab completes file names, and another existing file is replaced only after you confirm. The file holds the text exactly as it is — nothing reaches the database until you save the panel with ^K X.

Search and replace works in the panel as in the SQL editor: ^K F finds (options r replace, c match case, a all without asking), ^L finds the next match, ^R replaces — each match is highlighted and the bottom line asks y / n / a / Esc. Only the panel's text changes; ^_ undoes the whole replace.

Rows are found by their ROWID, so the result must come from one table and include a ROWID column. e in the object tree opens such a query for a table in a new tab (select rowid, col1, … from table); in your own SQL write e.g. select rowid, e.* from emp e. Without a ROWID, for joins, computed columns, binary columns (RAW, BLOB) and read-only connections, u says why it can't edit.

Inserting and deleting rows. i inserts a new row: sqlcli asks for the value of each of the result's table columns in turn (New row: ID (number, empty = NULL) [1/3]; Esc cancels the whole insert) and runs INSERT … VALUES (:1, …) RETURNING ROWID. The new row appears below the current one, with its ROWID, so it can be edited at once. d deletes the current row after a yes/no question (DELETE … WHERE ROWID = :rowid). Both work in the grid and in the record view, in the tab's transaction: F9 commits, F8 rolls back and puts the grid back as it was (edited values return, inserted rows go, deleted rows come back). Insert needs a result of one table; delete also needs its ROWID column.

Fetching rows

A query first fetches query.max_rows rows (default 1000). If it has more, the query stays open on the server, the status says 1000 row(s) fetched, more available., and the row count in the title gets a + (row 1/1000+).

  • Scrolling (arrows, PgDn, mouse wheel) to within a page of the last fetched row fetches the next max_rows rows.
  • End fetches all remaining rows in batches of 5000, showing Fetching… N rows in the status bar, then selects the last row.
  • Ctrl-C stops a fetch. Rows already fetched stay in the grid; the rest are discarded.
  • To always get every row, set query.fetch_all = true. Every query then fetches all its rows right away, and Ctrl-C stops it the same way.

Running another statement, rollback (F8) or commit (F9) closes the open query. The rows in the grid stay, but no more can be fetched.

Memory

Every fetched row is held in memory. Millions of wide rows can take gigabytes, so prefer a WHERE clause, or watch the counter and press Ctrl-C.

Exporting

Press e in the results pane to save the result to a file. sqlcli asks for the file name (it offers result.csv, then the last name you used); the extension picks the format.

ExtensionFormat
.csvComma-separated, header row, quoted where needed (RFC 4180)
.tsvTab-separated, header row
.jsonAn array of objects, one per row, keys in column order
  • All rows are exported, not only those on screen. If the query has more rows on the server, sqlcli fetches them first (Fetching all rows for export… N); Ctrl-C stops that and cancels the export.
  • NULL is an empty field in CSV/TSV and null in JSON. NUMBER columns are JSON numbers, written exactly as Oracle returned them; everything else is a string, dates as YYYY-MM-DD HH:MI:SS.
  • Duplicate column names (select a.id, b.id …) become ID and ID_2 in JSON.
  • An existing file is only replaced after you confirm. The file is written under a temporary name first, so a failed export never leaves half a file.

The selected row is shown in blue (ui.selection_color, a 256-colour number or "#rrggbb"); while the results pane doesn't have focus it stays marked in dim grey.

How values are shown

  • NULL appears as a grey (null). In Oracle an empty string is NULL.
  • Dates appear as YYYY-MM-DD HH:MI:SS. Timestamps with fractional seconds add microseconds.
  • RAW values appear as hex, CLOBs as their text.
  • Columns are as wide as their widest value, up to 50 characters. Longer values are cut with …; open the record view with Enter to read them in full. Line breaks inside values show as ⏎.

For DML and DDL the pane shows messages such as 3 row(s) updated. with the elapsed time. Errors are shown in red and start with the Oracle error code.

DBMS_OUTPUT

Output from DBMS_OUTPUT.PUT_LINE appears in the results pane below the statement's message, as with SET SERVEROUTPUT ON in SQL*Plus.

PL/SQL procedure successfully completed.  (3ms)
── Output (2 line(s)) ──
Hello from PL/SQL
second line
  • It's collected after every statement: PL/SQL blocks, CALL, DML that fires triggers, and queries calling functions that print.
  • If a block fails, the lines it printed before the error appear below the error message.
  • F7 (whole script) shows the output of all statements together.
  • Long output scrolls with the arrows, PgUp/PgDn, Home/End and the mouse wheel; ← → scroll long lines sideways. The title shows lines 1-15/202.

  • There's no size limit (DBMS_OUTPUT.ENABLE(NULL)). Set query.dbms_output = false to turn it off.

Sessions (F10)

A session is the set of open SQL tabs: for each tab its connection and its SQL text, plus which tab was active. Sessions are stored in the same SQLite file as the history.

Press F10 or ^K E to open the session window, or Ctrl-S to save the open tabs straight away.

Once a session is loaded or saved it's the current session: its name is shown in the top-left corner of the screen (before the tab list when several tabs are open), and Ctrl-S saves it again at once, without asking. Without a current session Ctrl-S asks for a name. To save under another name, use s in the session window. Deleting the current session clears its name.

With ui.save_session_on_exit = true (the default) the current session is also saved when you quit sqlcli (^K X, Ctrl-C, closing the last tab), and the terminal shows sqlcli: session "NAME" saved afterwards. Without a current session nothing is saved. Set it to false (or "no") to turn this off. It lists saved sessions, newest first, with the time they were saved, the number of tabs and their connections.

KeyAction
s / Ctrl-SSave the open tabs as a session (asks for a name; offers the current session's name or the date and time; asks before overwriting)
EnterLoad the selected session: it replaces the open tabs, reconnects each one and puts every tab's cursor at the top-left corner
d / DelDelete the selected session (asks first)
Esc / F10Close the window

Loading closes the current tabs' sessions. If a transaction is open, sqlcli asks first, because it will be rolled back; while a statement is running, loading is refused. A tab whose connection is no longer in the config file opens unconnected, and the status bar names the missing connection.

Some terminals use F10 themselves (for example to open their menu); turn that off in the terminal's settings if F10 doesn't reach sqlcli.

11Configuration file

The file is ~/.config/sqlcli/config.toml, or $XDG_CONFIG_HOME/sqlcli/config.toml, or the path given with -config. It's plain TOML that you can edit in any text editor. Changes take effect the next time sqlcli starts.

A complete example with every setting:

[oracle]
  lib_dir = "/usr/local/oracle"   # Instant Client dir; empty = $ORACLE_HOME

[editor]
  tab_width = 4          # spaces inserted by Tab; also expands pasted tabs
  auto_indent = true     # Enter keeps the current line's indentation
  syntax_highlight = true # colour SQL; also "yes" / "no"
  completion = true       # code completion; also "yes" / "no"

[query]
  max_rows = 1000        # rows per fetch; more on scroll or End
  fetch_all = false      # true = fetch all rows of every query at once
  timeout_seconds = 0    # cancel statements after N seconds; 0 = never
  auto_commit = false    # true = commit every statement immediately
  dbms_output = true     # show DBMS_OUTPUT in the results pane
  substitution = true    # SQL*Plus &variables at start; also "yes" / "no"

[ui]
  mouse = true           # wheel scrolls; hold Shift to select text
  show_connections = true # connections panel visible at start (F2 toggles)
  record_page = 10       # records PgUp / PgDn move in the record view
  save_session_on_exit = true # save the current session when quitting; also "yes" / "no"
  selection_color = "24" # selected result row background: 0-255 or "#rrggbb"

[history]
  path = ""              # SQLite file; empty = ~/.local/state/sqlcli/history.db
  max_entries = 500      # entries listed in the history browser

[[connections]]
  name = "ora"
  user = "scott"
  password_env = "SQLCLI_PASSWORD"   # read the password from this variable
  connect_string = "ORCL.EXAMPLE"    # TNS alias

[[connections]]
  name = "prod-readonly"
  user = "report"
  password = "secret"                # stored in plain text
  connect_string = "dbhost:1521/PROD"
  read_only = true                   # only SELECT / WITH / EXPLAIN / DESC

[[connections]]
  name = "admin"
  user = "sys"
  password_env = "ORA_SYS_PW"
  connect_string = "dbhost:1521/ORCLPDB1"
  sysdba = true                      # connect AS SYSDBA

14Troubleshooting

DPI-1047: Cannot locate a 64-bit Oracle Client library

Instant Client wasn't found. Set ORACLE_HOME to the Instant Client directory (the one containing libclntsh.so), or set oracle.lib_dir in the configuration file.

ORA-12154: could not resolve the connect identifier

The TNS alias is unknown. Check that TNS_ADMIN points to the directory with tnsnames.ora and that the alias is spelled correctly, or use an Easy Connect string (host:port/service) instead.

ORA-12541: Cannot connect. No listener

The host or port is wrong, or the database listener is down.

ORA-01017: invalid username/password

Wrong credentials. Oracle passwords are case-sensitive. With password_env, check that the variable is exported in the shell that starts sqlcli. Repeated failures can lock the account.

A key does nothing (^_ undo, F-keys)

Some terminals and tmux setups intercept or translate keys. Try the alternatives listed under Undo, or check your terminal's key settings. In tmux, set -g extended-keys on helps with Ctrl combinations.

A statement takes too long

Press Ctrl-C to cancel it, or set query.timeout_seconds.

I can't select text with the mouse

sqlcli uses the mouse wheel, so the terminal passes mouse clicks to it. Hold Shift while selecting (most terminals), or set ui.mouse = false.

A PL/SQL block fails, or F5 runs too much

End every PL/SQL block with a line holding only /. Until that line, sqlcli treats everything after BEGIN or DECLARE as part of the block.
